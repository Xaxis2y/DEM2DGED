# dem2dged test suite

Three layers, fastest first. Run all of them from the **Anaconda Prompt**
with the project's dedicated environment active — never from `base`.

```bat
conda activate DGED
cd /d C:\path\to\dem2dged_v0.41
```

If the environment does not exist yet, create it first (`install.bat`, or
`conda create -n DGED python=3.11 gdal numpy pytest -c conda-forge`).
Installing GDAL into `base` is the single most common cause of the
dependency conflicts and import failures this project hits.

---

## 1. `audit_pure.py` — no GDAL required (seconds)

```bat
python audit_pure.py
```

Stubs `osgeo` entirely, then checks the things that can be verified without
a raster: filename round-trips through the validator's patterns for every
product level, tile geometry, converter↔validator agreement on field widths,
template placeholder coverage, the elevation sanity-check heuristics, the
auto-optimize dispatch, and version consistency across every file that
declares a version.

Expected output ends with `RESULT: 0 problem(s)`.

## 2. `pytest` — unit + integration (a minute or two)

```bat
pytest -v
```

* `tests/test_lib.py` — pure library units and the version-consistency
  checks. Runs anywhere `dem2dged_lib` imports.
* `tests/test_validator.py` — the validator's filename patterns,
  `overall_result()`, and regression tests for the v0.30 / v0.31 / v0.34 /
  v0.38 / v0.39 / v0.41 fixes, plus end-to-end runs of `run_validation()`.
* `tests/test_converters.py` — real GEO and UTM conversions of synthetic
  DEMs generated by `tests/conftest.py`, then inspection of the tiles that
  were actually written.

Markers (`pytest.ini`):

```bat
pytest -m unit           :: fast, no gdalwarp needed
pytest -m integration    :: real conversions, needs gdalwarp on PATH
pytest -m "not slow"
```

Tests that need the `gdalwarp` **executable** skip themselves if it is not
on `PATH`. Seeing a block of skips means the environment is incomplete, not
that the code is fine — check `where gdalwarp`.

## 3. `run_verification.py` — full end-to-end harness (several minutes)

```bat
python run_verification.py
```

The 19-step release harness: GEO and UTM at every data type and resampler,
equatorial zero-padding and the UTM northing clamp, the high-latitude GEO
longitude-zone factors, the southern hemisphere, a real EGM96→EGM2008
transform, the aspect sanity check, and the data-type-aware predictor.
This is the one to run before cutting a release.

## Notes for anyone editing the suite

* **`output_dir` is per-test and must stay that way.** It resolves to a
  fresh `tempfile.mkdtemp()` and is removed on teardown. Before v0.38 it was
  one session-wide `output/` directory shared by every test, so one test's
  leftover tiles were still on disk when the next globbed `*.tif` expecting
  only its own — `test_utm_names_are_zero_padded` failed on a leftover
  GEO-named file rather than on anything wrong with UTM naming.
* `geo_dem` / `utm_dem` / `equator_utm_dem` are session-scoped on purpose:
  they are read-only inputs, and regenerating them per test is pure
  overhead.
* No test may depend on operator-supplied DEM data, network access, or a
  previous test's output.
