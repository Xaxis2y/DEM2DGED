Quick Start Guide · v0.48

dem2dged

Convert any raster DEM to military-standard DGED tiles — point-and-click with the GUI, or scripted from the command line.

✨ What's new in v0.48

v0.48 is a documentation-only release — no change to tile geometry, resampling algorithms, filenames, or metadata. It explains why elevation accuracy degrades faster on mountainous terrain than on flat terrain at a fixed product level, adds the DGED spec's predicted horizontal/vertical accuracy goals to the level table below, and recommends -resample optimize for high-relief sources — see the "Terrain relief and accuracy" box under Product levels. Before that, v0.47 fixed a fairness bug in -resample optimize's accuracy measurement: cubic-family candidates were scored on their raw, unclamped reconstruction, while delivered tiles are clamped into the source's true range before being written — so a few overshoot pixels at sharp discontinuities (never actually shipped) could make cubic-family methods look less accurate than what you actually receive. Fixed, and Cubic B-Spline is now a fourth measured candidate alongside Nearest/Bilinear/Cubic. Tile generation, DGED tables and the auto default are unchanged from v0.46. What changed before that is how the tool behaves when something goes wrong: several failure modes that used to be silent, misleading, or fatal now stop early and say what to do. Highlights:

  • Terrain relief, level and accuracy explained (v0.48) — the level table now shows the DGED spec's predicted horizontal/vertical accuracy goal per level, not just GSD, and a new box explains why steep terrain needs a matching level and the right resampling method, not just a finer level. See "Product levels" below.
  • Fairer optimize accuracy ranking + Cubic B-Spline candidate (v0.47) — cubic-family resamplers are now scored on the same source-range-clamped values a real delivery would actually contain, instead of their raw unclamped overshoot. See selftest_optimize_resampling.py.
  • Configurable elevation tolerance (v0.46) — 5m (DGIWG strict) or 10m (standard, default) for Section H2, selectable in the GUI and via -max-diff.
  • Environment diagnostic (v0.45) — run python dem2dged_env.py when an import fails. The classic ModuleNotFoundError inside an activated environment is almost always the command form: typing script.py instead of python script.py makes Windows launch a different interpreter entirely. The old message blamed the environment, which sent people reinstalling packages that were never missing.
  • Works on non-UTF-8 consoles (v0.44) — packaging and verification used to die on a Korean/Japanese/Chinese console (UnicodeEncodeError: 'cp949' codec…) because the scripts printed decorative ✓/✗ glyphs. All console output is plain ASCII now, and paths containing non-Latin characters no longer crash it.
  • Fails fast, once, with a fix (v0.42) — an unknown -resample value used to produce one gdalwarp error per tile and then report success over an empty folder. A missing gdalwarp, or a source raster with no EPSG code, died with a raw traceback naming neither the file nor the problem. All three are now checked before any work starts. A run that produces no tiles is a hard error.
  • Seam coverage closed (v0.43) — half of the tile-edge reconciliation (the north/south row pass) had never been exercised by any test. Now covered, along with Int16 output and the level 0–3 filename form, and the release gate builds and runs the frozen exes.
  • Data-type-aware compression — Float32 tiles (all UTM levels, GEO level 3+) use the floating-point LZW predictor; Int16 tiles keep the integer predictor. Smaller and more format-correct, still lossless (spec 13.1).
  • Resampling control + comparison — pick Nearest / Bilinear / Cubic / Average, or optimize (measures which method reconstructs your DEM most accurately). A side-by-side Resampling Comparison Report ranks them.
  • Elevation sanity check — catches an aspect / slope / direction raster fed in by mistake before any tiles are written.
  • Seamless tile edges — adjacent tiles are made bit-identical along their shared post row/column (spec 13.2).
  • Cubic overshoot clamp — cubic-family resamplers can no longer ship elevations outside the source's true min/max.
  • Equatorial UTM fix — northings are zero-padded to the spec width and clamped to the valid [0, 10 000 000] m band (no more negative-northing names).
  • Accurate validation — the source-comparison no longer mistakes the EGM2008 geoid height for an error on SRTM-style inputs.

🗺️ Background — What are DEM and DGED?

If you are already familiar with these terms, skip ahead to Step 1. Otherwise, read on — it only takes two minutes.

DEM

Digital Elevation Model

A DEM is simply a digital map of the Earth's surface height — a grid of values where each cell stores the elevation (in metres) of that spot on the ground.

Think of it like a photograph, but instead of colour each pixel holds an altitude number. DEMs are produced from satellites, aircraft LiDAR scanners, or radar systems.

Common DEM sources:
SRTM (NASA, free, 30 m global) · Copernicus DEM (ESA, free, 30/10 m) · LiDAR surveys (very high resolution, often national) · TanDEM-X (12 m global)
Common file format: GeoTIFF (.tif) — a georeferenced image file
DGED

Defense Gridded Elevation Data

DGED is a military packaging standard for elevation data, defined by DGIWG (NATO's Defense Geospatial Information Working Group). It does not invent a new file format — it specifies exactly how a GeoTIFF elevation file must be structured, named, and documented so that any military system from any NATO nation can read it reliably.

DGED is the successor to the older DTED format and will eventually replace it as the primary elevation exchange format across NATO forces.

What DGED enforces:
• Vertical datum: EGM2008 (global gravity-based height reference)
• Tile size: fixed per resolution level
• File naming: encodes location, level, security class
• Metadata: ISO 19115-2 XML sidecar file alongside every tile
• Compression: LZW · No-data value: −32767

DGED defines numbered levels — higher numbers mean finer detail. Pick the level that matches your input data's native resolution. Upsampling to a higher level than your data supports won't add real detail.

💡
GEO vs UTM — which mode?
GEO (WGS-84 lat/lon) is the NATO standard and works everywhere on the globe — use this unless you have a specific reason not to. UTM uses a metric grid tied to a specific zone — useful when downstream tools need metre-based coordinates.

What does this tool do?

  • 📥
    Takes any DEM as input GeoTIFF, VRT, SRTM HGT, or any raster GDAL can open
  • 🔧
    Re-projects, resamples and slices Applies the correct CRS, EGM2008 vertical datum, nodata, and LZW compression
  • 📦
    Outputs DGED-compliant tiles One .tif + one .xml sidecar per tile, named to spec
ℹ️
Two output modes: GEO (WGS-84 lat/lon, used globally) and UTM (metric grid, good for local/regional work). GEO is the default.

🖱️ Easiest way — the GUI (recommended)

No commands needed. Two ways to launch it:

  • 🚀
    Option A — double-click dist\dem2dged.exe Fully standalone: no Python or GDAL installation required on the machine.
  • 🐍
    Option B — run python dem2dged_gui.py From an activated DGED conda environment (see Step 1–2 below).

Using the GUI — six clicks:

  • 1️⃣
    + Add Files… Select one or more DEM files (hold Ctrl for multiple). Supported: .tif, .tiff, .vrt, .hgt, .img, .asc — anything GDAL reads.
  • 2️⃣
    Browse… — pick the output folder With "Create subfolder per file" checked (default), each DEM gets its own folder named <input name>_dged_output — e.g. daejeon.tif → daejeon_dged_output\
  • 3️⃣
    Choose the output mode GEO (WGS-84, NATO standard) or UTM (metric). In UTM mode the Zone box activates — leave AUTO or type e.g. 52N.
  • 4️⃣
    Pick the product level The list adapts to the mode: GEO offers 0–9, UTM offers 4b–9. Level 5 (~2 m) is the default.
  • 5️⃣
    (Optional) Advanced settings Source type, security class and product version — written into tile filenames. The Source vertical field applies a real EGM2008 geoid transform if your input heights use a different datum (e.g. EGM96). Defaults are fine for most uses.
  • 6️⃣
    ⚙ Convert Progress bar + live log per tile. ■ Stop halts after the current tile; re-running later resumes where it left off (completed tiles are skipped). A validation report is generated automatically when the batch finishes — see below.
🔨
Rebuilding the exe after a code update: open Anaconda Prompt, then conda activate DGED → cd path\to\dem2dged → build_exe.bat. The build scripts (v0.13+) verify GDAL is present and always use the active environment's Python, so the "No module named 'osgeo'" build problem cannot recur. The GUI title bar shows the version it was built from.

The scripts need Python 3 and GDAL. The easiest way is Anaconda. (Skip this entirely if you only use dist\dem2dged.exe.)

Windows

Double-click install.bat in the DEM2DGED folder, or run in a terminal:

Linux / macOS

conda create --name DGED --channel conda-forge gdal python=3.10 -y
✅
Once the environment is created you never need to reinstall. Just activate it each time you open a new terminal.
2

Activate the environment & navigate to the folder

Windows (Anaconda Prompt)

conda activate DGED
cd path\to\dem2dged

Linux / macOS (Terminal)

conda activate DGED
cd ~/dem2dged
💡
You'll know the environment is active when you see (DGED) at the start of your terminal prompt.
3

Run the conversion

The main command is always:

python dem2dged.py  <input_file>  <output_folder>  [options]

▶ Simplest run (GEO, ~2 m resolution)

python dem2dged.py  my_dem.tif  dged_output

▶ UTM output, auto-detect zone

python dem2dged.py  my_dem.tif  dged_output  --mode utm

▶ UTM, specify zone, higher resolution

python dem2dged.py  my_dem.tif  dged_output  --mode utm  --zone 32N  --level 6

▶ See all options

python dem2dged.py  --help
✅
The output folder is created automatically if it doesn't exist. Progress is printed as a percentage. When done you'll see All done!
⚠️
If a run is interrupted, just re-run the same command — it skips tiles that are already complete. Delete the last tile first if it may be partially written.

★ Default. Pick a level that matches your input data's native resolution — upsampling doesn't add information. The accuracy column is the DGED spec's predicted goal for typical terrain at that level (Table 6 — also the --abs-vacc default), not a guarantee for any specific file; see below for why.

⛰️
Terrain relief and accuracy. A level's GSD is the spacing between measured posts — everything in between is filled in by resampling, not measured. On flat terrain that's a safe approximation; on steep terrain (ridgelines, canyon walls, cliff edges) elevation can change tens of metres within a single post spacing, so the resampler is effectively inventing values, not interpolating them. Measured proof: on steep real-world terrain, Bilinear and Cubic Convolution showed 6–10 m sample-window error while Nearest Neighbor — which copies the nearest post instead of blending across the slope — stayed near 0 m on the same source. Two things actually help: pick the level that matches your source data's real resolution (a higher level cannot invent detail that was never there), and use --resample optimize on rugged sources, which measures Nearest / Bilinear / Cubic / Cubic B-Spline against your actual DEM and picks whichever reconstructs it most accurately — instead of guessing, or converting the same file three times by hand.

What does the output look like?

For each tile the tool creates two files. Levels 4b and up use the full form; levels 0–3 (GEO only) use a shorter form with no product-type letter or tile-size indicator, since they're delivered by whole square degree:

# GEO example (level 4b+)
DGEDL5GtD_5530N00930E_A_U_01.tif    ← elevation raster
DGEDL5GtD_5530N00930E_A_U_01.xml    ← ISO 19115-2 metadata sidecar

# GEO example (level 0-3, short form)
DGEDL2_27N056E_A_U_01.tif

# UTM example
DGEDL5UtD_32N6210_452_A_U_01.tif
DGEDL5UtD_32N6210_452_A_U_01.xml

Data type is Int16 for levels 0–2, Float32 for level 3 and up. An optional producer-organisation code (--org) can be embedded in any level's filename right before the coordinate.

Every run also writes two product-level files alongside the tiles: TABLE_OF_CONTENTS.xml (lists every file in the folder) and, when a run produces more than one tile, a <product>_COLLECTION.xml with collection-level metadata.

✅
Validation runs automatically — both the GUI and the CLI write a DGED_Validation_Report.html (+ plain-text copy) to the output folder right after conversion, no extra step needed. Disable it with --no-validate / the GUI checkbox.

Run it manually any time (e.g. against tiles from an older run):

python dem2dged_validate.py  dged_output  -src my_dem.tif

Checks naming, headers, grid alignment, XML sidecars, NoData integrity, tile-edge consistency and (with -src) coverage + statistics against the original DEM. Prints RESULT: PASS or lists every problem found.

Or inspect a single tile manually:

gdalinfo DGEDL5GtD_5530N00930E_A_U_01.tif

Look for AREA_OR_POINT=Point in the output — that confirms the header is correct.

Troubleshooting

  • ❓
    "No module named 'numpy'" / "'osgeo'" — but the environment IS activated Almost always the command form, not the environment. Typed as script.py rather than python script.py, Windows follows the .py file association and runs a different interpreter — conda activate changes PATH, not the file association, so the prompt still shows the environment name while the script runs elsewhere. Always type python first. To confirm which interpreter you are on: python dem2dged_env.py. Do not reinstall the packages — they were never missing.
  • ❓
    "UnicodeEncodeError: 'cp949' codec can't encode character" A non-UTF-8 console (Korean cp949, Japanese cp932, Chinese cp936). Fixed in v0.44 — every script prints plain ASCII now, and non-Latin characters in a path no longer crash it. On an older copy, run chcp 65001 first, or set PYTHONIOENCODING=utf-8.
  • ❓
    "cannot determine the EPSG code" The source raster's CRS has no EPSG code (a bare ESRI WKT, a local CRS, a plain .asc grid, or no projection at all). Tag it first, then re-run: python -m osgeo_utils.gdal_edit -a_srs EPSG:4326 my_dem.tif. Use the module form — on conda for Windows the GDAL utilities ship as modules, so gdal_edit.py is often not on PATH.
  • ❓
    "GDAL cannot open" error Check the path to your DEM. Use forward slashes or quote the path if it contains spaces.
  • ❓
    exe fails with "No module named 'osgeo'" The exe was built from a Python environment without GDAL. Rebuild it: conda activate DGED → build_exe.bat. Since v0.13 the build scripts detect this before building.
  • ❓
    "unknown UTM product level" for levels 0–3 Levels 0–3 exist only in GEO mode. Switch to GEO or pick level 4b–9 (the GUI level list adapts automatically).
  • ❓
    Wrong UTM zone (Norway / Svalbard) Auto-detect is approximate. Override with --zone 33N (or whichever zone you need).
  • ❓
    Empty border tiles Normal — DGED requires a one-cell overlap at tile edges. Filter out tiles smaller than ~1 KB if unwanted.
  • ❓
    Run stopped halfway Delete the last (incomplete) tile, then re-run the same command. The tool skips tiles that already have a completed .xml sidecar.
