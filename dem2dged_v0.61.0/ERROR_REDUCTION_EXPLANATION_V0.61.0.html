How the conversion error was reduced

v0.61.0 makes the resampling decision match the operation that is actually performed: a DEM is evaluated at the requested DGED post spacing, with physical units, native-resolution source data, explicit metadata gates, and a metric that cannot silently turn into a different test.

The central idea

The largest improvement was methodological. The optimizer must measure the same kind of transformation that production performs. When the target DGED grid is coarser than the source DEM, the relevant question is not “which filter reconstructs an already fine grid best?” It is “which candidate produces the least error when the source is genuinely reduced to the target posts?”

Result: candidate ranking is now based on a real decimation-and-score path whenever the source-to-target ratio requires decimation. The report identifies the primary metric instead of presenting a fallback as if it were equivalent evidence.

What caused avoidable errors before

The failure modes were not all interpolation-formula problems. Several were measurement and data-contract problems that could make a mathematically reasonable filter look better or worse for the wrong reason.

Measurement direction

Upsampling was not a valid proxy for decimation

At large source-to-target ratios, reconstructing a dense grid and scoring it can invert the ranking of candidates. Production then reduces the source, but the optimizer has selected a method using a different experiment.

Coordinate units

Degrees were not metres

Geographic rasters describe spacing in angular units. A ratio calculated directly from degrees does not represent physical ground spacing and can select an unsuitable resampler or prefilter.

Large sources

Pre-decimating the test window changed the ratio

Reducing a source window before measuring the candidate made the test easier than the real conversion. The measured ratio no longer matched the source and target grids supplied by the operator.

Data contract

Unknown metadata could be treated too optimistically

Missing vertical reference, non-point registration, scale/offset, or unit information can create a large apparent accuracy error. Without a gate, the tool could produce a result that looked valid but was not comparable.

Comparison terminology

Primary path

DECIMATE-AND-SCORE

The source is reduced to the requested target spacing and scored at the target posts. This is the preferred metric when the production conversion is genuinely decimating.

Legacy comparison

HOLD-OUT

Some source posts are withheld, the remaining posts are reconstructed to the full grid, and the withheld values are scored. It measures reconstruction quality, not the same operation as native decimation.

Degraded evidence

holdout_fallback

The real decimation setup was unavailable, so the report retained the hold-out result and recorded the fallback reason. It must not be read as equivalent to decimate-and-score.

How the optimizer now works

  1. Measure the grids in physical space.
    For projected data, source and target spacing are measured in metres. For geographic data, the tool converts angular spacing to ground distance rather than dividing degree values directly.
  2. Keep the source at native resolution.
    For large inputs, the tool selects bounded native-resolution windows. It does not quietly pre-shrink the source before deciding which candidate is best.
  3. Determine the actual operation.
    If the target posts are coarser, each candidate is evaluated through a real decimation path. Candidate methods include nearest, bilinear, cubic, cubicspline, lanczos, and average where supported by the conversion path.
  4. Score at the requested posts.
    The result is compared with a native-source reference at the target locations. Six subpixel phases are used so that the decision is not dependent on one fortunate grid alignment.
  5. Select by the primary metric.
    RMSE is intentionally primary because it penalizes large errors and provides a stable scalar for candidate ranking. The report also records P90 absolute error and maximum absolute error, so a good average cannot hide a damaging tail event.
  6. Protect the output range.
    The output is checked against the exact native source extrema. This limits overshoot from higher-order interpolation without changing the measured source range through rounding.

Metadata preflight is an error barrier

A conversion cannot be called accurate if the tool does not know what the elevation values mean. v0.61.0 records the source inspection and preflight decisions before tile production.

HOLDRequired metadata is missing, inconsistent, or unsafe to interpret. The conversion is stopped before tiles are produced.
EXPERT OVERRIDE--allow-unknown-source-metadata records the decision explicitly. It permits a controlled workflow, but it is not an accuracy pass.
PASSHorizontal CRS, point registration, metre interpretation, valid scale/offset, and vertical reference meet the preflight contract.

The evidence is retained in files such as source_inspection.json and source_preflight.json, so a later review can tell whether the tool used verified metadata or an explicit exception.

What this does not prove

Accuracy boundaries matter. The conversion optimizer can reduce resampling and candidate-selection error, but it cannot repair incorrect source elevations, an unknown vertical datum, a bad georeferencing transform, or terrain features absent from the source DEM.
  • It does not establish absolute CE90, LE90, or other product-accuracy statistics without independent control data.
  • It does not prove that the source DEM's vertical datum, units, or acquisition quality are correct merely because metadata fields are present.
  • It does not guarantee that the controlled analytic-terrain ranking will be identical for every terrain type, scale, or GDAL build.
  • It does not replace target-application acceptance, visual inspection, or mission-specific DGED/DTED conformance review.

Recommended operator practice

Before conversion

  • Confirm horizontal CRS and authority.
  • Confirm that raster registration is pixel-is-point when the workflow requires post values.
  • Confirm elevation units, scale/offset, and vertical reference.
  • Keep the original source and preflight JSON with the release record.

During conversion

  • Use -resample optimize when method selection should respond to the source and target ratio.
  • For high-relief or strong-decimation cases, use the real decimate-and-score path.
  • Do not treat an expert metadata override as proof of accuracy.
  • Review the report's metric family and fallback state.

After conversion

  • Run terrain QA appropriate to the product and region.
  • Inspect edge behavior, nodata boundaries, and high-relief features.
  • Compare against independent control when absolute accuracy is required.
  • Record the tool version, GDAL version, source metadata, and validation evidence.
