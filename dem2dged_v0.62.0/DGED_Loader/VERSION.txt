Changes in v0.62.0:
- New reference finder (dem2dged_reference.py, reference_catalog.json): looks up
  open lidar DEMs that cover your source extent - NRCan HRDEM (Canada, STAC
  API) and USGS 3DEP 1 m / 1/3 arc-second (US, TNM Access API) - and clips ONLY
  your area (no resampling, window capped at 40 million cells) into a small
  GeoTIFF with a *_reference.json sidecar (identifier, SHA-256, declared
  accuracy, vertical datum, license, warnings).
- Coverage check: a dataset's outline can be far larger than the area it has
  heights for (the first live test clipped two tiles that held no data over
  the test box). Search now samples each of the best candidates over your
  area, shows "Data in area", ranks datasets without data last, and the
  automatic choice only takes a dataset with at least 90% valid heights.
- GUI: "Find reference..." button next to the independent-reference Browse
  button. Search lists datasets with a "fit for the selected DGED level"
  column; Download clip fills the reference path and identifier boxes.
- Command line: python dem2dged_reference.py --source dem.tif --level 5 --list
  (or --bbox MINLON MINLAT MAXLON MAXLAT; --pick N to clip).
- Suitability rule of thumb (not a DGIWG rule): OK if the reference's declared
  LE90 <= the level's vertical random 90% limit / 3; MARGINAL if <= limit / 2.
  No open dataset reaches OK for levels 6 and finer; those need surveyed
  ground control points.
- Network use happens only when you press Find reference / run the command.
  Only the bounding box is sent. Declared accuracies are the providers', not
  measured by DEM2DGED, and a download does not prove independence.
- No conversion, tiling, resampling, metadata or compliance logic changed.
- Test: TEST_REFERENCE_V0.62.0.py (offline unit tests + live Ottawa / Washington
  DC clip test, writes logs\reference_test_*.log / .json).

Changes in v0.58.0:
- Added "Show DGED Differences" to DGED_Loader.pyt.
- The tool resolves exactly one validation result set, loads
  elevation_diff.tif as the signed DGED-minus-source difference, loads and
  styles error_mask.tif, recovers the original source path from the conversion
  manifest or terrain_metrics.json, and optionally loads the DGEDL* tiles.
- It reports stored bias, MAE, RMSE, P95, and maximum absolute difference, and
  explains that these are conversion-fidelity metrics rather than independent
  absolute-accuracy evidence.
- Parent folders containing multiple validation result sets are rejected so
  unrelated source and output datasets cannot be mixed silently.
- Added ArcGIS Pro licensed-runtime smoke-test logging and expanded the offline
  fake-ArcPy harness to cover discovery, source recovery, layer grouping,
  difference semantics, red mask symbology, metric reporting, and error paths.

Changes in v1.0.0 (initial standalone release):
- DGED_Loader.pyt: ArcGIS Pro Python Toolbox, "Load DGED Tiles" tool.
  Main folder + multiple hand-picked subfolders (both optional, at least
  one required), recursive on/off toggle, optional group-layer
  organisation, optional Build Pyramids pass. Verified against a mock
  arcpy harness (27 checks: parameter defaults/order, multivalue parsing
  via both the iterable-value and valueAsText-fallback code paths,
  recursive vs. non-recursive walking, folder/tile de-duplication,
  missing-.xml-sidecar warnings, group create/add/remove sequencing, the
  no-folders-provided error path) -- real arcpy.mp calls were not
  exercised, since no ArcGIS Pro install is available in the build
  environment; test end to end in Pro before relying on it for a real
  delivery.
- DGED_Load_Tool_script.py: same logic as a flat GetParameterAsText
  script, for building a native .atbx via ArcGIS Pro's Script Tool
  wizard (see ATBX_WIZARD_GUIDE.md). 4 additional parity checks against
  the same mock harness.
- .atbx was deliberately NOT hand-built: it's a zipped, Esri-proprietary
  format with no published schema, and Esri's own guidance is to build
  it inside Pro rather than by hand. DGED_Loader.pyt is the guaranteed-
  working primary deliverable; ATBX_WIZARD_GUIDE.md covers the ~2-minute
  guided path to a genuine .atbx if you specifically need that container.

Installation:
1. Extract the DEM2DGED v0.58.0 release, or `DGED_Loader_v0.58.0.zip`.
2. In ArcGIS Pro, Catalog pane > browse to this folder > double-click
   DGED_Loader.pyt to add it as a toolbox.
3. Open a map, run "Load DGED Tiles" from inside it.

See README.md for the parameter reference and troubleshooting, and
ATBX_WIZARD_GUIDE.md for the native-.atbx path.
